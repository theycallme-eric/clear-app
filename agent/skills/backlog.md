# Backlog Skill

**Context:** The backlog tracks all pending work, organized by priority. Location: `docs/BACKLOG.md`

## Reading the Backlog

1. **Priority Sections:**
   - High Priority: Address soon, possibly blocking V1
   - Medium Priority: Important but not blocking
   - Low Priority: Nice to have, future versions

2. **Item Format:**
   ```
   - [ ] **[Title]** - [Brief description]
     - Priority: High / Medium / Low
     - Type: Bug / Enhancement / Feature / Tech Debt / Idea
     - Added: [Date]
     - Context: [Why this matters]
   ```

## Updating the Backlog

1. **When Starting a Task:**
   - No change needed (item stays unchecked)

2. **When Completing a Task:**
   - Move the item to the "Completed Items" section
   - Change `- [ ]` to `- [x]`
   - Add completion date and any relevant notes

3. **When Adding New Items:**
   - Add to appropriate priority section
   - Also add to "By Type" section for cross-reference
   - Include enough context for future understanding

4. **Quick Add:**
   - Use the "Quick Add Section" at bottom for fast capture
   - Organize into proper sections later
